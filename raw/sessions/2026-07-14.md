**Context:** User troubleshooting `now-sdk init` failing with a syntax error while `now-sdk --help` worked fine.

**Key Exchanges:**
- **pedro:** `now-sdk --help` works but `now-sdk init` throws `Unexpected token '?'` (optional chaining syntax error).
- **Root cause identified:** Shell is zsh, but nvm was only loaded in `~/.bashrc`, not `~/.zshrc`. Interactive zsh sessions fell back to system Node (`/usr/bin/node` v12.22.9) instead of nvm-managed Node 24.11.1. `--help` doesn't use modern syntax so it survived; `init`'s interactive prompt library (inquirer) does.
- **Fix:** Added the nvm loader block to `~/.zshrc` (same block already present in `~/.bashrc`). Verified in a fresh zsh session — `now-sdk init` now correctly launches the template picker.

**Lessons Learned:**
- **General (discovered in pedro):** When a CLI tool works with one subcommand but fails with another, suspect a Node/runtime version mismatch — not a tool bug. `--help` is often safe on old runtimes; interactive prompts (inquirer, etc.) frequently use modern JS syntax.
- **General (discovered in pedro):** nvm's shell loader must be added to every shell's RC file independently. Having it in `~/.bashrc` does nothing for zsh users. Always check `~/.zshrc` when a user's primary shell is zsh.
- **pedro:** `now-sdk` shebang is `#!/usr/bin/env node` — it resolves whatever `node` is first on `$PATH`, making it sensitive to which shell/RC file is active.

**Action Items:**
- **pedro:** Open a new terminal or run `source ~/.zshrc` for the fix to take effect in the current shell session.
