## Issue

# Symptoms

Here is the scenario :

1) Assume storage clusters A and B have access to the same datazone.

2) Run discovery on Storage Cluster A and a storage Cluster record will be created on cmdb\_ci\_storage\_cluster table.

3) Run discovery on Storage Cluster B.

4) The previously created Storage Cluster A record will be deleted and Storage cluster B record will be created in the cmdb\_ci\_storage\_cluster table.

# Release

Kingston,London,Madrid

# Cause

1) The Storage clusters are deleted based on the deletion strategy set to Delete for the CI type : cmdb\_ci\_storage\_cluster on the EMC Isilon Pattern.

More info on deletion strategy can be found in the below doc :   
[https://docs.servicenow.com/csh?topicname=deletion-strategy.html&version=latest](https://docs.servicenow.com/csh?topicname=deletion-strategy.html&version=latest) 

2) EMC Isilon pattern converts datazones to a Storage Server record and Storage Server is the main CI type for the EMC Isilon pattern.

3) When we discover both Storage Clusters, the Storage Server record created is the same since these Storage Clusters have access to the same datazone.

4) So when we discover Storage Cluster A , the Storage Cluster B record gets deleted based on the deletion strategy set to Delete as the Main CI is the same Storage Server.

5) In order to resolve this issue, we need to make sure a separate Storage Server Record is created for each Cluster.

6) The Storage Server Records are identified based on Serial Number and Name, so we need to make sure the Serial number generated in the pattern for the Storage Server is unique depending on the Cluster being discovered.

# Resolution

1) In the EMC Isilon pattern, step no 22 adding serial number to data zones 

change the EVAL script to the below code :   
  
var rtrn;   
var base64 = new Packages.org.apache.commons.codec.binary.Base64();   
var ioutils = new Packages.org.apache.commons.io.IOUtils();   
var path = ${data\_zones\[\].path};   
var name = ${data\_zones\[\].name};   
var clusterName = ${cluster\_info\[1\].name};   
var pathStr = path + '';   
var nameStr = name + '';   
var clusterStr = clusterName + '';   
var combined = pathStr + ":" + nameStr + ":" + clusterStr;   
var output = base64.encodeBase64String(ioutils.toByteArray(combined)) + '';   
output = output.toLowerCase();   
rtrn = output; 

2) Previously , The Serial number for the storage server is generated by performing a base64 encoding on the combination of the datazone name and the datazone path.

3) The above solution provided will make sure we take into consideration the name of the cluster as well for base64 encoding , so that a unique serial number is generated based on the Storage Cluster being discovered
