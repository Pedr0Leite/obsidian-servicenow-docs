## Issue

When importing data, auto-numbering functionality does not avoid pre-existing numbers and could result in "Unique Key violation" errors  

Problem

* * *

Several forms on the instance use the auto-numbering functionality using the **Number Maintenance** (sys\_number) table. However, this, assume the existing data does not have the a number below the current number on sys\_number table.

  
  
 Symptoms

* * *

You will recognize this problem when the following conditions are satisfied:

-   The problematic table column must be configured with a dynamic default value of "Get Next Padded Number"
-   There is a unique index on the column on the table that prevents duplicate numbers.
-   "Number definition" of the prefix must have a counter which is below the maximum number existing on the records (Eg: Max existing number on the instance is INC0000055, and the counter shows 0000054)

Creating a new record, and saving, which would trigger a new number generation, would end up with Duplicate entry (Unique Key violation) for the autonumbering column.

Cause

* * *

This is because some table columns might be configured with dynamic numbering with "Get Next Padded Number" (javascript:getNextObjNumberPadded() in code) to take advantage of the platform generating record numbers in sequence.  
  
This feature does not take care of the the uniqueness of the previous generated numbers, and if the records in the instance are imported from data source, migrated from an instance, modified manually or the number definitions are modified to generate numbers that might already exist on the system, duplicate entry errors might occur.

  
Resolution

* * *

-   To handle the situation,
    -   navigate to **System Definition** -> **Number Maintenance,**
    -   select the appropriate prefix you are using,
    -   click "Show Counter" related link,
    -   and increase the counter to a value that does not currently exist on the instance.

-   Or, use a business rule that executes on the table using auto-numbering to ensure the numbers are not used beforehand:

var curNum = current.number + '';  
if(curNum) {  
  var gr = new GlideRecord('incident');  
  gr.addQuery('number', curNum);  
  gr.query();  
  if(gr.getRowCount() > 0) {  
    var newNum = getNextObjNumberPadded();  
    current.number = newNum;  
  }  
}
