# obsidian-servicenow-docs

Obsidian vault and AI-navigable knowledge base for ServiceNow platform development, plus a Claude Code agent pipeline for building ServiceNow scoped apps.

The vault also acts as **persistent memory for Claude Code**: session logs, imported chats, and Graphify-generated codebase knowledge graphs live alongside the docs, so agents start each session with full context instead of re-reading everything.

## Claude Code memory & knowledge graphs

This vault doubles as Claude Code's long-term memory, following the [Graphify + Obsidian + Claude Code](https://github.com/safishamsi/graphify) setup:

- **Session continuity** — `/resume` reads the latest `logs/` entries and project decisions; `/save` writes a new session log with wikilinks. Both commands are defined in `CLAUDE.md`.
- **Codebase graphs** — from any project repo, `graphify . --obsidian --obsidian-dir <vault>/graphify/<project>` generates graph notes here plus a queryable `graphify-out/graph.json` in the repo. Agents query the graph before reading raw code (3-layer rule in each project's `CLAUDE.md`).
- **Refreshing graphs** — `graphify . --update` after structural changes, or automatically via `graphify hook install` (post-commit).

### Graph view filters

| Filter | Shows |
|--------|-------|
| `path:graphify` | only code-graph nodes |
| `-path:graphify -path:chats` | only human-authored notes |
| `tag:chat-import` | only imported chats |

## Navigation

Use **`ServiceNowOfficialDocs/INDEX.md`** to find any official-docs topic without browsing directories.

For custom `now-assist-ai/` content, use **`ServiceNowOfficialDocs/now-assist-ai/llms.txt`**.

For personal notes, browse `Notion/ServiceNow/` by topic folder.

For building a new ServiceNow feature end-to-end, see **`ClaudeAgents/README.md`** and start with the `orchestrator` agent.

For the structure of a specific codebase, check **`graphify/<project>/`** (or the project's `graphify-out/graph.html` for an interactive view).
